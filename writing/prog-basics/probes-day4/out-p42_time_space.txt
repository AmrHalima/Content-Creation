== 42.1  the cached version: real item count and real bytes ==
baseline: sys.getsizeof({}) = 64 bytes (empty dict)
n items | dict items | container bytes | key objects | value objects | total bytes
    100 |      100 |            4688 |        2800 |          2800 |       10288
   1000 |     1000 |           36952 |       28000 |         28000 |       92952
   5000 |     5000 |          147544 |      140000 |        140000 |      427544

pinned example: squares 1..1000 -> 1000 items, 36952 + 28000 + 28000 = 92952 bytes
that is 90.8 KiB for the cached version
note: the container alone does NOT include the int objects; a frame that prints only
getsizeof(d) understates the tradeoff by roughly 4x. Both numbers are printed above so
the builder can choose, and the total is the honest one.

== 42.2  the recomputed version: real bytes ==
recompute holds nothing: sys.getsizeof of no container = 0 bytes of extra storage
(one temporary int at a time; the loop variable is reused)
tradeoff at n=1000: pay 92952 bytes to avoid recomputing 1000 multiplications

== 42.3  the time half, measured on this machine (MACHINE-SPECIFIC: label or omit) ==
200,000 lookups in the cached dict:   0.0064s = 32 ns each
200,000 recomputed multiplications:   0.0015s = 8 ns each
ratio: the cached path is 4.3x SLOWER than just multiplying
=> THE PART'S OWN EXAMPLE DEMONSTRATES THE OPPOSITE OF ITS CLAIM. 'caching results uses
   more memory but saves time' is true in general; for `squares[i] = i*i` specifically it
   is false - you pay 92,952 bytes to avoid a multiplication a dict lookup costs more than.
   Do not put a stopwatch number on screen for 42's squares example; the honest screen
   pair is BYTES CACHED vs WORK SAVED, and the work has to be big enough to matter:

== 42.4  the same trade where it DOES pay, so the part is not a false advertising case ==
200 calls, cached:      0.0000s = 0.1 us per call
200 calls, recomputed:  0.0488s = 244.1 us per call
speedup x2774 at this n, bought with cache_info() below
cache_info() verbatim AFTER the timed calls: CacheInfo(hits=200, misses=1, maxsize=None, currsize=1)
=> hits=200, misses=1, entries kept=1
The honest on-screen pair for 42 is therefore:
   CACHED:    92952 bytes stored for n=1000 squares, 1 lookup, work saved only when the work is big
   RECOMPUTED: 0 extra bytes stored, 1000 multiplications repeated
Any 'saves time' number on screen must be labelled as measured on this machine, or cut.
