== 35.3  PINNED CONFIGURATION for the frame: m = 16 bits, k = 3 hashes ==
before:  0000000000000000
'cat' positions: [6, 3, 13]  -> distinct bits set: 3
after cat: 0001001000000100   (3 of 16 bits are 1)
'dog' positions: [3, 6, 8]  bit values at those positions: [1, 1, 0]
'dog' already shares 2 position(s) with 'cat' [3, 6]; the 1 still 0 is enough -> filter says DEFINITELY NOT
this is the lesson: 2 of 3 bits matching is still 'definitely not', because ALL k must be 1.

== 35.4  the CTA: why can there be no false negative? ==
bits 'cat' owns: [3, 6, 13]
after 5 more inserts, bits: 1111101110111110
re-probe 'cat': True -> still YES; bits are only ever set to 1, never cleared
so a member can never probe to a 0. False negatives would need a bit to be UNset,
and nothing in the structure does that.

at m = 16 the filter saturates fast: it is a demo, not a design.
Any on-screen 'tiny memory' claim must carry its m, or the part claims a property the
pinned table does not have. m = 16 bits is literally 2 bytes.
