== 39.2  the script's exact example: 'Capacity 4, append a 5th item' ==
after 4 appends, capacity = 4   <- the script says 4: TRUE
append the 5th -> capacity = 8
did it grow on the 5th append? True
growth factor at THIS resize: 2.0
=> the example is not just true, it lands exactly on the first resize CPython performs.
   That makes it the best possible frame, and it also means the words 'spare room' need
   care: at n=4 there is no spare left, so the 5th append is not covered by slack.

=> after the 1st append CPython reserves 4 slots, so appends 2, 3 and 4 are free. That is

CAUTION for the frame: capacity(n) via list(range(n)) is NOT the same sequence as via
appends - a range/list literal sizes its block differently. Every number above comes from
repeated .append(), matching the hook 'how does append stay fast'.

== 39.4  amortized cost, counted as copied elements ==
resize points up to 64 items: ['n=1 (0->4)', 'n=5 (4->8)', 'n=9 (8->16)', 'n=17 (16->24)', 'n=25 (24->32)', 'n=33 (32->40)', 'n=41 (40->52)', 'n=53 (52->64)']
number of resizes in 64 appends: 8
64 appends copy 176 elements in total = 2.75 copies per append
so 64 appends cost 64 + 176 = 240 units of work = 3.75 per append.
=> 'one resize is expensive, spread across many appends the average stays constant' is a
   measured ratio here, not a slogan. Screen: 8 resizes, 176 copies, 2.75 per append.

== 39.5  growth factor, reported honestly ==
ratio at each resize (new capacity / old capacity), by append order:
  n =  1:  0 ->  4  = first allocation, no factor to quote
  n =  5:  4 ->  8  = x2.000
  n =  9:  8 -> 16  = x2.000
  n = 17: 16 -> 24  = x1.500
  n = 25: 24 -> 32  = x1.333
  n = 33: 32 -> 40  = x1.250
  n = 41: 40 -> 52  = x1.300
  n = 53: 52 -> 64  = x1.231
=> there is NO single growth factor to print. Measured over the first eight resizes the
   ratio runs from x2.000 down to x1.231 and is NOT monotonic (x1.250 at n=33, then x1.300
   at n=41). The textbook '~1.125 asymptote' is not something these measurements show, so
   do not put it on screen as a measured number. The script's hedge ('depends on the
   language') understates it: in ONE language it also depends on WHICH resize.
   If the frame prints a factor, print the one for the resize it shows (x2 for 4 -> 8).
