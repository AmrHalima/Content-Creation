# 150 Dev Shorts: 14-Day Production Plan and Scripts

*English series + a separate Syrian-Arabic series · 60-second vertical videos for beginner-to-mid developers · written to be edited with AI*

## 1. How to Use This Doc

- **Structure:** Sections 1 to 5 are the playbook. Then Day 1 to Day 14 each hold that day’s English scripts and Syrian-Arabic scripts. The last section has the publishing calendar, metrics, and AI editing prompts.
- **Two series, not a translation:** Both cover the same 150 topics, but the Arabic hooks, analogies, and calls to action are written for how Arab audiences engage. Don’t translate one into the other.
- **Script length:** Each draft is about 70 to 90 spoken words plus on-screen code. With pauses for visuals and the end loop, that lands around 45 to 60 seconds. Read each one aloud once, then trim or stretch it with the AI prompts in the last section.
- **Tags:** `[B]` beginner, `[M]` mid-level, then the engagement type: Quiz, Debate, Myth, Save, Tag, Challenge (Arabic: سؤال، نقاش، خرافة، احفظ، منشن، تحدي).
- **Script anatomy:** Hook (0-3 s), Explain (3-25 s), Example (25-45 s), CTA and loop (45-60 s).
- **Before recording:** Run every code snippet yourself. Have AI flag anything that could be wrong, then confirm it.

## 2. The Engagement Formula (English Series)

- **Hook (0-3 s):** Start with the code or the result already on screen. Use one of five patterns: a surprising result (“why does '5' + '5' equal 55?”), a common mistake, a myth, a stakes line (“interviewers ask this”), or a direct challenge.
- **Explain (3-25 s):** One idea, one analogy, no undefined jargon. Beginners stay if they feel smart. Mid-level devs stay if they learn one sharp detail.
- **Example (25-45 s):** Show, don’t tell. One to three lines of code or a tiny diagram, with a pause so people can read it.
- **CTA and loop (45-60 s):** Ask something answerable in one word or one number, then end on a line that flows back into the hook so the video loops.

**Engagement levers (rotate them; never use the same one three videos in a row):**

1. **Quiz:** “What prints?” with the answer in a pinned comment. Drives comments and replays.
2. **Debate:** Honest, low-stakes splits (Return vs Print, tabs vs spaces). Never bait with wrong facts.
3. **Myth:** “You were told X. Here’s what’s actually true.”
4. **Save:** Cheat-sheet framing: “save this for your interview.”
5. **Tag:** “Send this to the dev who still...”
6. **Challenge:** Viewers reply with their own solution, and you reply back with a video to the best ones.

**Reply habit:** Answer comments in the first hour, with a short video reply when the question is good. It keeps threads alive and builds a loyal audience.

**Metrics per video:** 3-second hold, average percent watched, shares and saves per 1,000 views, comments per 1,000 views, follows per 1,000 views. Treat these as things to test, not rules.

## 3. The Syrian-Arabic Series: What Is Different

- **Dialect:** Spoken Syrian (شامي), not Modern Standard Arabic. Words like شو، ليش، هلق، كتير، بدّك، عم، رح، مو. Keep technical terms in English (variable, function, array), because that is how Arab developers actually talk and search.
- **Tone:** A friendly older-brother or study-group voice: humor, light teasing, direct address (“يا شباب”، “يا صاحبي”). Less lecture, more conversation.
- **Analogies from daily life:** المونة (labeled jars), الدور عالفرن, السرفيس, الشاي, الصحن والأكلة. Use things your viewer has physically seen.
- **Engagement styles to test:** Arabic comment sections tend to reward tagging a friend (منشن), “احفظ الفيديو”, picking a team (فريق X ولا فريق Y), relatable struggle humor (الجامعة، المقابلات، الفريلانس، الشغل عن بعد), and visible, personal replies from the creator. Keep whatever your analytics confirm.
- **Value framing:** Tie topics to real outcomes: مقابلة شغل، مشروع التخرج، فريلانس، شغل برّا.
- **Captions:** Arabic captions are essential since many people watch muted. Keep English terms in Latin letters inside the Arabic sentence, and keep code blocks left-to-right.
- **Hashtags:** Mix #برمجة #تعلم\_البرمجة #مبرمج with English tags (#programming #coding) for search.
- **Posting time:** Start with evenings in Syria time (UTC+3), then adjust after two weeks of data.
- **Sensitivity:** Keep humor light and inclusive. Avoid politics, religion, and jokes about hardship.

## Day 1: Programming Basics I (Topics 1-11)

**Day 1 focus:** Lock your visual template. Code card on screen from second 0, big captions, and the same end-card on every video.

### English Scripts

**1. What is a variable?** `[B]` · Quiz

- **Hook:** “Every app you use remembers things. Here’s the trick behind it.”
- **Explain:** “A variable is a labeled box. You put a value inside, give the box a name, and use that name whenever you need the value again. Change what’s inside and the name stays the same.”
- **Example:** On screen: `score = 10`, then `score = score + 5`, then `print(score)`.
- **CTA:** “What prints if score starts at 100? Drop the number below.”

**2. Data types: int, float, string, boolean** `[B]` · Quiz

- **Hook:** “Why does '5' + '5' give you 55?”
- **Explain:** “Every value has a type: integers for whole numbers, floats for decimals, strings for text, booleans for true or false. The type decides what an operation means. Plus on numbers adds. Plus on strings glues.”
- **Example:** `5 + 5` gives 10, but `'5' + '5'` gives '55'.
- **CTA:** “Guess what `'5' * 3` gives in Python. Comment it.”

**3. Strings vs. characters** `[B]` · Save

- **Hook:** “A string isn’t one thing. It’s a lot of tiny things in a row.”
- **Explain:** “A character is a single symbol, like 'a'. A string is a sequence of characters, each with a position, and counting starts at zero. That’s why you can grab the third letter, loop over it, or slice it.”
- **Example:** `word = 'code'`, then `word[0]` gives 'c' and `word[1:3]` gives 'od'.
- **CTA:** “Save this and try slicing your own name.”

**4. What is a function?** `[B]` · Tag

- **Hook:** “If you copy-paste the same code twice, you’re missing something.”
- **Explain:** “A function is a named, reusable recipe. Write the steps once, give them a name, and call it whenever you need it. Fix the recipe once and every call gets fixed.”
- **Example:** `def greet(name): print('Hi ' + name)`, then `greet('Sara')` and `greet('Omar')`.
- **CTA:** “Send this to the friend who still copy-pastes.”

**5. Parameters vs. arguments** `[B]` · Myth

- **Hook:** “Parameters and arguments are not the same thing, and interviewers know it.”
- **Explain:** “A parameter is the placeholder in the function definition. An argument is the real value you pass when you call it. The parameter is the empty seat. The argument is the person who sits in it.”
- **Example:** `def add(a, b)`: a and b are parameters. `add(2, 3)`: 2 and 3 are arguments.
- **CTA:** “Comment ‘seat’ if that finally made it click.”

**6. Return values vs. side effects** `[M]` · Debate

- **Hook:** “Two functions can look identical and behave completely differently.”
- **Explain:** “A return value hands a result back to the caller. A side effect changes something outside the function: printing, writing a file, editing a global. Functions that only return are easier to test and trust.”
- **Example:** `def double(x): return x*2` versus `def double(x): print(x*2)`.
- **CTA:** “Team Return or Team Print? Pick a side.”

**7. Scope: local vs. global** `[B]` · Quiz

- **Hook:** “Why does your variable ‘not exist’ one line later?”
- **Explain:** “Scope decides where a variable can be seen. A variable made inside a function is local: it lives and dies there. One made outside is global and visible almost everywhere. Prefer local so bugs stay close to home.”
- **Example:** `def f(): x = 1`, then `print(x)` raises a NameError.
- **CTA:** “Comment the error name you’ve seen the most.”

**8. Constants and immutability** `[B]` · Save

- **Hook:** “The safest variable is the one that can’t change.”
- **Explain:** “A constant is a name you agree never to reassign, like TAX\_RATE. An immutable value can’t be modified after it’s created, like a string in Python. Less change means fewer surprise bugs.”
- **Example:** `MAX_USERS = 100`, and `s = 'hi'` then `s[0] = 'H'` raises a TypeError.
- **CTA:** “Save this for your next code review.”

**9. If/else conditionals** `[B]` · Challenge

- **Hook:** “Every decision your app makes comes down to this.”
- **Explain:** “If/else lets your program choose a path. If the condition is true, one block runs. Otherwise the other does. Add elif for more conditions, and the first match wins.”
- **Example:** `if age >= 18: print('Welcome')` then `else: print('Sorry')`.
- **CTA:** “Challenge: write it as a one-liner. Show me in the comments.”

**10. Switch statements** `[B]` · Debate

- **Hook:** “A switch is just a tidy pile of if statements.”
- **Explain:** “When one value can match many cases, a switch checks it against each case and runs the match. In many languages you need a break, or execution falls through to the next case. Python uses match instead.”
- **Example:** `switch(day){ case 'sat': ...; break; default: ... }`
- **CTA:** “Switch or if-else chain: what do you reach for?”

**11. For loops vs. while loops** `[B]` · Quiz

- **Hook:** “Pick the wrong loop and you’ll hang your program.”
- **Explain:** “Use a for loop when you know how many times to repeat, or when you’re walking through a collection. Use a while loop when you repeat until a condition changes, like waiting for valid input.”
- **Example:** `for i in range(3):` versus `while not done:`
- **CTA:** “Which do you use more? For or while?”

## Day 2: Basics II, Arrays, Linked Lists (Topics 12-22)

**Day 2 focus:** Mix visuals. Shoot topics 14, 17, and 18 face-to-camera and the rest with code cards, so the feed doesn’t look repetitive.

### English Scripts

**12. Infinite loops and how to avoid them** `[B]` · Quiz

- **Hook:** “Your program froze and your laptop fan is screaming. Here’s why.”
- **Explain:** “An infinite loop happens when the condition never becomes false. Usually you forgot to update the variable the condition depends on. Before running any loop, ask: what changes each round, and what ends it?”
- **Example:** `while i < 5: print(i)` with no `i += 1`.
- **CTA:** “Spot the missing line? Comment it.”

**13. Break and continue** `[B]` · Challenge

- **Hook:** “Two tiny keywords that save you from messy loops.”
- **Explain:** “Break exits the loop immediately. Continue skips the rest of this round and jumps to the next one. Use break when you’ve found what you need. Use continue to ignore items you don’t care about.”
- **Example:** `if n < 0: continue` and `if n == target: break`.
- **CTA:** “Challenge: find the first even number in a list using break. Post your code.”

**14. What is recursion?** `[B]` · Myth

- **Hook:** “To understand recursion, you must first understand recursion.”
- **Explain:** “Recursion is a function that calls itself on a smaller version of the same problem. Each call trusts the next one to solve a piece, until the problem is so small the answer is obvious.”
- **Example:** `def fact(n): return 1 if n <= 1 else n * fact(n-1)`, then `fact(4)` gives 24.
- **CTA:** “Drop the best recursion joke you know.”

**15. Base case in recursion** `[B]` · Quiz

- **Hook:** “Forget this one thing and you’ll get a stack overflow.”
- **Explain:** “The base case is where recursion stops. Without it, the function calls itself until the call stack runs out. Every recursive function needs a base case and a step that moves toward it.”
- **Example:** `def f(n): return f(n-1)` raises a RecursionError in Python.
- **CTA:** “What’s the base case for summing a list? Comment it.”

**16. Type casting and coercion** `[B]` · Debate

- **Hook:** “In JavaScript, '5' + 3 is '53', but '5' - 3 is 2. Yes, really.”
- **Explain:** “Casting is you converting a type on purpose, like int('5'). Coercion is the language doing it silently. Explicit is safer, because coercion rules can surprise you.”
- **Example:** `int('5') + 3` gives 8, while `'5' + 3` in JavaScript gives '53'.
- **CTA:** “Should languages coerce types automatically? Yes or no.”

**17. Null, nil, and None** `[B]` · Save

- **Hook:** “The inventor of null called it his billion-dollar mistake.”
- **Explain:** “Null, nil, and None all mean ‘no value here’. It’s not zero and it’s not an empty string. The danger: calling a method on nothing crashes your program, so check before you use it.”
- **Example:** `user = None`, then `user.name` raises an AttributeError.
- **CTA:** “Save this, then tell me your worst null bug.”

**18. Comments and why they matter** `[B]` · Debate

- **Hook:** “Good code doesn’t need comments. Agree or disagree?”
- **Explain:** “Comments should explain why, not what. If you have to explain what the code does, rename things until it explains itself. Save comments for decisions, warnings, and tricky reasons.”
- **Example:** `# retry 3 times: the payment API drops requests under load` versus `# add 1 to i`.
- **CTA:** “Agree or disagree? Defend your side below.”

**19. Operators: arithmetic, logical, comparison** `[B]` · Quiz

- **Hook:** “One of these operators is not what you think.”
- **Explain:** “Arithmetic operators do math. Comparison operators return true or false. Logical operators combine conditions: and, or, not. And watch out: a single equals sign assigns, a double equals compares.”
- **Example:** `x = 5` versus `x == 5`. In Python, `7 // 2` gives 3 while `7 / 2` gives 3.5.
- **CTA:** “What’s `7 % 3`? Comment it.”

**20. Short-circuit evaluation** `[M]` · Tag

- **Hook:** “Your code skips half your condition, and that’s a feature.”
- **Explain:** “With and/or, the language stops as soon as the answer is known. In A and B, if A is false, B never runs. That lets you guard risky checks, like making sure something exists before reading it.”
- **Example:** `if user and user.is_admin:` is safe even when user is None.
- **CTA:** “Tag the dev who writes nested ifs for this.”

**21. Arrays** `[B]` · Save

- **Hook:** “Need 100 variables? You need one array.”

## Day 4: Advanced Structures and Big O (Topics 34-44)

### English Scripts

**34. Circular buffers** `[M]` · Save

- **Hook:** “How does a log keep only the latest 100 entries and never grow?”
- **Explain:** “A circular buffer is a fixed-size array where the write position wraps back to the start after reaching the end. New data overwrites the oldest. It never grows or shifts, which is great for streaming data, audio, and logs.”
- **Example:** Size 3: write A, B, C, then D overwrites A.
- **CTA:** “Save this for system design questions.”

**35. Bloom filters** `[M]` · Myth

- **Hook:** “A data structure that can say ‘definitely not’ but only ‘maybe’ for yes.”
- **Explain:** “A Bloom filter uses a bit array and several hash functions to check membership in tiny memory. If it says no, the item is definitely absent. If it says yes, it might be a false positive. Databases and caches use it to skip expensive lookups.”
- **Example:** Adding 'cat' sets 3 bits. Checking 'dog' finds one bit still 0, so it’s definitely not there.
- **CTA:** “Why can’t a Bloom filter give false negatives? Comment your guess.”

**36. LRU cache** `[M]` · Quiz

- **Hook:** “How does a cache decide what to throw away?”
- **Explain:** “An LRU cache evicts the least recently used item when it’s full. Every read moves an item to the front. Combine a hash map for fast lookup with a doubly linked list for fast reordering, and every operation runs in constant time.”
- **Example:** Capacity 2: put A, put B, get A, then put C evicts B.
- **CTA:** “Capacity 2: put A, put B, get A, put C. What gets evicted?”

**37. Array vs. linked list tradeoffs** `[B]` · Debate

- **Hook:** “Arrays win more often than textbooks admit.”
- **Explain:** “Arrays give instant access by index and sit in one contiguous block, which CPUs love. Linked lists make inserts and deletes cheap once you’re at the node, but finding it is slow and each node costs extra memory. For most real work, arrays win.”
- **Example:** Access item 500: array O(1), linked list O(n).
- **CTA:** “When did you actually use a linked list at work? Be honest.”

**38. Hash collisions** `[M]` · Quiz

- **Hook:** “What happens when two keys want the same spot?”
- **Explain:** “A collision is when two keys hash to the same index. Chaining stores a small list in each slot. Open addressing probes for the next free slot. Good hash functions and resizing keep collisions rare, so lookups stay fast.”
- **Example:** 'ab' and 'cd' both land in slot 3, so slot 3 holds a chain: ab → cd.
- **CTA:** “Chaining or open addressing: which would you pick?”

**39. Dynamic arrays and resizing** `[M]` · Save

- **Hook:** “How does append stay fast when arrays have a fixed size?”
- **Explain:** “A dynamic array secretly keeps spare room. When it fills up, it allocates a bigger block, copies everything over, and carries on. One resize is expensive, but spread across many appends the average cost stays constant.”
- **Example:** Capacity 4, append a 5th item, and the capacity grows. The growth factor depends on the language.
- **CTA:** “Save this for when someone asks about amortized cost.”

**40. Tuples vs. lists** `[B]` · Quiz

- **Hook:** “Lists change. Tuples don’t. So why have both?”
- **Explain:** “A list is mutable: you can add, remove, and change items. A tuple is immutable: once created, it’s fixed. Use tuples for data that shouldn’t change, like coordinates. A tuple of hashable items can even be a dictionary key.”
- **Example:** `point = (3, 4)`, then `point[0] = 9` raises a TypeError.
- **CTA:** “Can a list be a dictionary key? Yes or no.”

**41. Big O notation** `[B]` · Save

- **Hook:** “How do engineers say ‘this code gets slow’ without a stopwatch?”
- **Explain:** “Big O describes how runtime grows as input grows. O(1) is constant, O(n) grows in a straight line, O(n²) shows up with nested loops, and O(log n) halves the work each step. It ignores constants and focuses on the trend.”
- **Example:** One loop over n items is O(n). A loop inside a loop is O(n²).
- **CTA:** “Save this. What’s the Big O of looking up a key in a hash map?”

**42. Time vs. space complexity** `[B]` · Debate

- **Hook:** “You can often trade memory for speed. Here’s how.”
- **Explain:** “Time complexity is how long code takes. Space complexity is how much memory it uses. They often trade off: caching results uses more memory but saves time, while recomputing saves memory but costs time.”
- **Example:** Store squares in a dictionary to avoid recalculating them.
- **CTA:** “Speed or memory: which do you sacrifice first?”

**43. Binary search** `[B]` · Challenge

- **Hook:** “Find one number among a billion in about 30 steps.”
- **Explain:** “Binary search works on sorted data. Check the middle. If your target is smaller, discard the right half. If larger, discard the left. Repeat. Each step halves the search space, so it takes log n steps.”
- **Example:** Find 7 in `[1, 3, 5, 7, 9]`: the middle is 5, go right, found 7.
- **CTA:** “Challenge: about how many steps for 1,000 items? Comment it.”

**44. Bubble sort** `[B]` · Myth

- **Hook:** “The sorting algorithm everyone learns and nobody uses.”
- **Explain:** “Bubble sort walks through the list, swapping neighbors that are out of order. The largest value bubbles to the end each pass. It’s easy to understand but slow, O(n²), so real code uses faster sorts.”
- **Example:** `[3, 1, 2]` → `[1, 3, 2]` → `[1, 2, 3]`.
- **CTA:** “Which sort do you actually use in real life?”

- **Explain:** “Dijkstra’s algorithm finds the cheapest path in a weighted graph. It always expands the closest unvisited node, using a priority queue, and updates the best-known distances to that node’s neighbors. It requires non-negative weights.”

- **Hook:** “How Sudoku solvers undo their mistakes.”
- **Explain:** “Backtracking builds a solution step by step. When a choice leads to a dead end, it undoes that choice and tries the next one. It’s depth-first search over the space of choices, with early pruning.”

**55. Sliding window** `[M]` · Save

**56. Divide and conquer** `[M]` · Save

- **Hook:** “The strategy behind merge sort, quick sort, and binary search.”
- **Explain:** “Divide and conquer has three steps: split the problem into smaller pieces, solve each piece, then combine the answers. It works best when the pieces are independent and the combining step is cheap.”

**57. Union-Find** `[M]` · Quiz

- **Hook:** “Are these two people in the same friend group? Answer in near-constant time.”
- **Explain:** “Union-Find tracks which items belong to the same group. Find returns a group’s representative. Union merges two groups. With path compression and union by rank, each operation is nearly constant time.”
- **Example:** `union(1, 2)`, `union(2, 3)`, then `find(1)` equals `find(3)`.
- **CTA:** “After union(1,2) and union(3,4), are 1 and 4 connected? Yes or no.”

**58. Topological sort** `[M]` · Quiz

- **Hook:** “How a build tool knows what to compile first.”
- **Explain:** “A topological sort orders the nodes of a directed acyclic graph so every dependency comes before the things that need it. If the graph has a cycle, no valid order exists.”
- **Example:** Edges A → B, A → C, B → D, C → D. One valid order: A, B, C, D.

- **Hook:** “Same answer. One takes tens of billions of steps. The other takes fifty.”

**60. Amortized analysis** `[M]` · Save

- **Hook:** “An operation can be slow sometimes and still fast on average.”
- **Explain:** “Amortized analysis averages the cost of an operation over a whole sequence. Appending to a dynamic array is occasionally expensive because of a resize, but across many appends the average cost per append is constant.”

**68. Composition over inheritance** `[M]` · Tag

- **Hook:** “Stop building deep inheritance trees.”
- **Explain:** “Composition builds objects by combining smaller parts, a ‘has-a’ relationship. It’s more flexible than inheritance: you can swap parts at runtime and avoid fragile hierarchies where changing the parent breaks every child.”

**69. Constructors** `[B]` · Quiz

- **Hook:** “The first code that runs when an object is born.”
- **Explain:** “A constructor is a special method that runs when you create an object. It sets up the initial state and enforces rules, like requiring a name. In Python it’s `__init__`. In JavaScript it’s `constructor`.”

**70. Static vs. instance methods** `[B]` · Quiz

- **Hook:** “Does this method need an object, or not?”
- **Explain:** “An instance method works on one specific object and its data. A static method belongs to the class itself and doesn’t touch instance data, like a utility function grouped under the class name.”
- **Example:** `user.get_name()` versus `Math.max(1, 2)`.
- **CTA:** “Can a static method read `self.name`? Yes or no.”

**71. Method overloading vs. overriding** `[M]` · Myth

- **Hook:** “These two words sound alike and mean very different things.”
- **Explain:** “Overloading is several methods with the same name but different parameters in one class. Overriding is a child class replacing a parent’s method with its own version. Not every language supports overloading, and Python doesn’t.”
- **Example:** Overloading: `print(int)` and `print(String)`. Overriding: `Dog.speak()` replaces `Animal.speak()`.

**72. The `this` / `self` keyword** `[B]` · Save

- **Hook:** “Who is ‘this’? Beginners get stuck right here.”
- **Explain:** “This, or self, is a reference to the current object. Inside a method, it lets you reach that object’s own data and methods. Without it, the code can’t tell which instance you mean.”

**73. SOLID principles overview** `[M]` · Save

- **Hook:** “Five letters that interviewers love.”
- **Explain:** “SOLID is five design principles: Single responsibility, Open/closed, Liskov substitution, Interface segregation, and Dependency inversion. Together they aim for code that’s easier to change, test, and understand.”

**74. Single Responsibility Principle** `[M]` · Quiz

- **Hook:** “A class should have one reason to change.”
- **Explain:** “The Single Responsibility Principle says each class or module should do one job. If one class handles data, formatting, and emailing, a change to any of them risks breaking the others. Split by reason to change.”
- **Example:** `Invoice` calculates totals, `InvoicePrinter` formats, `InvoiceMailer` sends.

**75. Open/Closed Principle** `[M]` · Debate

- **Hook:** “Add features without touching working code.”
- **Explain:** “Open/Closed says code should be open for extension but closed for modification. Instead of editing a big if-else every time you add a case, add a new class that plugs into the existing structure.”

**76. Liskov Substitution Principle** `[M]` · Myth

- **Hook:** “If it quacks like a duck but needs batteries, you have a problem.”
- **Explain:** “Liskov says a subclass must work wherever its parent is expected, without surprising the caller. If swapping a parent for a child breaks the code, the inheritance is wrong.”

- **Example:** `OrderService(notifier: Notifier)` instead of creating `EmailSender()` inside.

### English Scripts

**78. DRY (Don’t Repeat Yourself)** `[B]` · Debate

- **Hook:** “Copy-paste is a debt you pay back with interest.”
- **Explain:** “DRY means every piece of knowledge should live in one place. Fix a bug in one copy and you have to remember every other copy. But don’t over-apply it: merging code that only looks similar can create worse coupling.”

**79. KISS** `[B]` · Tag

- **Hook:** “The cleverest code is usually the worst code.”
- **Explain:** “KISS says keep it simple. Simple code is easier to read, test, and fix at 2 a.m. If a teammate needs ten minutes to understand your one-liner, rewrite it plainly.”
- **Example:** A nested ternary chain versus a clear if/else.
- **CTA:** “Tag the dev who writes one-liners nobody can read.”

**80. YAGNI** `[B]` · Debate

- **Hook:** “You aren’t going to need it.”
- **Explain:** “YAGNI means don’t build features or abstractions for needs you only imagine. Most guesses about the future are wrong, and unused code still costs maintenance. Build what you need now and refactor when the need becomes real.”
- **Example:** Adding a plugin system to an app that has one feature.

**81. Singleton pattern** `[M]` · Debate

- **Hook:** “One instance only. Handy, and often a trap.”
- **Explain:** “The Singleton pattern ensures a class has just one instance and gives global access to it. It suits things like a config or a logger, but it hides dependencies and makes testing harder, so use it sparingly.”
- **Example:** `Logger.getInstance()` always returns the same object.
- **CTA:** “Singleton: pattern or anti-pattern? Vote below.”

**82. Factory pattern** `[M]` · Quiz

- **Hook:** “Stop scattering `new` everywhere.”
- **Explain:** “A factory is a function or class that creates objects for you. Callers ask for what they need, like a ‘circle’, and the factory decides which class to build. It centralizes creation and keeps callers from depending on concrete classes.”
- **Example:** `shape = ShapeFactory.create('circle')`

**83. Observer pattern** `[M]` · Save

- **Hook:** “How does your app update the screen when data changes?”
- **Explain:** “In the Observer pattern, a subject keeps a list of observers and notifies them whenever it changes. Observers don’t poll. They subscribe. It’s the idea behind event listeners and reactive UI updates.”
- **Example:** `button.addEventListener('click', handler)`
- **CTA:** “Save this. Where have you used event listeners?”

**84. Strategy pattern** `[M]` · Quiz

- **Hook:** “Swap an algorithm without changing the code that uses it.”
- **Explain:** “The Strategy pattern puts interchangeable algorithms behind a common interface, and the caller picks one at runtime. It replaces long if-else chains with objects you can swap.”
- **Example:** `checkout.pay(CreditCard())` versus `checkout.pay(PayPal())`.
- **CTA:** “Name something in your app that could be a strategy.”

**85. Decorator pattern** `[M]` · Save

- **Hook:** “Add behavior without touching the original.”
- **Explain:** “The Decorator pattern wraps an object to add behavior while keeping the same interface. You can stack wrappers: logging around caching around the real call. Python’s @decorator syntax is the same idea for functions.”
- **Example:** `@timed` above `def load_data()` times every call.
- **CTA:** “Save this. What would you decorate first: logging or caching?”

**86. Adapter pattern** `[M]` · Tag

- **Hook:** “Plug a European charger into a US socket.”
- **Explain:** “The Adapter pattern wraps an incompatible class so it matches the interface your code expects. It lets you use old or third-party code without changing it, and the caller never knows what’s behind it.”
- **Example:** `LegacyPrinterAdapter` exposes `print(doc)` on top of an old `send_job(bytes)` API.

**87. Dependency injection** `[M]` · Save

- **Hook:** “Pass your dependencies in. Don’t create them inside.”
- **Explain:** “Dependency injection means a class receives what it needs from outside instead of building it. That makes classes easier to test, since you can pass in a fake, and easier to change, since nothing is hard-wired.”
- **Example:** `class OrderService: def __init__(self, notifier): ...`

**88. MVC architecture** `[B]` · Quiz

- **Hook:** “Why so many web apps split into three parts.”
- **Explain:** “MVC splits an app into Model for data and rules, View for what the user sees, and Controller for handling input and connecting the two. Each part can change independently, which keeps code organized.”
- **Example:** Click ‘Add’ → Controller → updates Model → View refreshes.

**89. Separation of concerns** `[B]` · Save

- **Hook:** “`a.b().c().d()` is a code smell.”
- **Explain:** “The Law of Demeter says an object should only talk to its immediate friends, not reach through them. Long call chains tie your code to the internal structure of other objects, so a small change deep inside breaks you.”
- **Example:** `order.customer.address.city` versus `order.shipping_city()`.

**91. Pure functions** `[B]` · Quiz

- **Hook:** “Same input, same output. Always.”
- **Explain:** “A pure function depends only on its inputs and has no side effects. Call it a thousand times with the same arguments and you always get the same result. That makes it easy to test, cache, and reason about.”
- **Example:** `add(a, b)` is pure. A function that uses `random()` or a global counter isn’t.

**92. First-class functions** `[B]` · Save

- **Hook:** “In many languages, functions are just values.”
- **Explain:** “First-class functions can be stored in variables, passed as arguments, and returned from other functions, just like numbers or strings. That unlocks callbacks, decorators, and much of functional programming.”

**93. Higher-order functions** `[M]` · Quiz

- **Hook:** “A function that takes or returns a function.”
- **Explain:** “A higher-order function accepts other functions as arguments, returns a function, or both. It lets you pass behavior around instead of just data, so you can reuse the same structure with different logic.”
- **Example:** `apply(f, x)` where `f` is `double` or `square`.

**94. Map, filter, reduce** `[B]` · Challenge

- **Hook:** “Three functions replace most of your loops.”
- **Explain:** “Map transforms every item. Filter keeps items that pass a test. Reduce combines everything into one value. Together they express what you want instead of the step-by-step how.”
- **Example:** `[1,2,3,4]` → map x\*2 → `[2,4,6,8]` → filter above 4 → `[6,8]` → reduce with + → 14.

**98. What is DNS?** `[B]` · Tag

- **Hook:** “The phone book of the internet.”

**141. Agile vs. waterfall** `[B]` · Debate

**143. Race conditions** `[M]` · Quiz

- **Hook:** “Two threads, one variable, wrong answer sometimes.”
- **Explain:** “A race condition happens when the result depends on the timing of concurrent operations. Two threads read the same value, both add one, and both write back, so one update is lost. Fix it with locks, atomic operations, or by avoiding shared state.”
- **Example:** `counter += 1` from two threads can give 1 instead of 2.
- **CTA:** “Start at 0, two threads each add 1. What results are possible?”

**144. Concurrency vs. parallelism** `[M]` · Myth

- **Hook:** “Concurrency and parallelism are not the same thing.”
- **Explain:** “Concurrency is dealing with many tasks at once by interleaving them, even on a single core. Parallelism is actually running tasks at the same time on multiple cores. Concurrency is structure. Parallelism is execution.”
- **Example:** One cook switching between three dishes is concurrent. Three cooks, one dish each, is parallel.
- **CTA:** “Can you have concurrency without parallelism? Yes or no.”

**145. Deadlocks** `[M]` · Quiz

- **Hook:** “Two programs, each waiting for the other forever.”
- **Explain:** “A deadlock happens when tasks each hold a resource the other needs, and none can proceed. Typical fixes: always acquire locks in the same order, use timeouts, and avoid holding one lock while waiting for another.”
- **Example:** Thread A holds lock 1 and wants lock 2. Thread B holds lock 2 and wants lock 1.
- **CTA:** “How would you prevent this? Comment your fix.”

**146. Garbage collection** `[M]` · Save

- **Hook:** “Who cleans up the memory you forgot about?”
- **Explain:** “Garbage collection automatically frees memory that your program can no longer reach. The runtime tracks which objects are still referenced and reclaims the rest. It prevents many memory bugs, but pauses and overhead are the trade-off.”
- **Example:** `x = Obj()` then `x = None`: the object becomes unreachable and can be collected.
- **CTA:** “Save this. Which language’s GC gave you trouble?”

**147. Stack vs. heap memory** `[M]` · Quiz

- **Hook:** “Where do your variables actually live?”
- **Explain:** “The stack holds function calls and local variables in a fast, automatic, last-in-first-out structure. The heap holds objects that outlive a single call, managed more flexibly but more slowly. Stack space is limited, which is why infinite recursion crashes.”
- **Example:** `int x = 5` lives on the stack. `new Object()` lives on the heap.
- **CTA:** “Which one overflows with infinite recursion? One word.”

**148. Compiled vs. interpreted languages** `[B]` · Debate

- **Hook:** “Is Python slow because it’s interpreted? It’s more complicated.”
- **Explain:** “A compiler translates your whole program into machine code before it runs. An interpreter executes code step by step at runtime. Many languages blur the line: Java compiles to bytecode, and Python compiles to bytecode that a virtual machine runs. Speed depends on the implementation.”
- **Example:** C: compile, then run. Python: run the script directly.
- **CTA:** “What was your first language: compiled or interpreted?”

**149. Debugging strategies** `[B]` · Challenge

- **Hook:** “The bug isn’t where you think it is.”
- **Explain:** “Reproduce the bug reliably first. Then narrow it down: read the error message, add prints or use a debugger, and bisect the code to find where reality diverges from your expectation. Explain the problem out loud to a rubber duck. Often you’ll spot it mid-sentence.”
- **Example:** `print(x)` before and after the suspicious line.
- **CTA:** “Challenge: what’s the weirdest bug you ever fixed? The best story gets pinned.”

**150. Idempotency** `[M]` · Quiz

- **Hook:** “Click ‘pay’ twice and get charged once. How?”
- **Explain:** “An operation is idempotent if doing it many times has the same effect as doing it once. Setting a value is idempotent. Incrementing is not. APIs use idempotency keys so retries after a timeout don’t create duplicates.”
- **Example:** `PUT /users/7` with `{name: 'Sara'}` is safe to repeat. `POST /orders` needs an idempotency key.

- **الهوك:** “البايثون بطيء لأنو interpreted؟ القصة أعقد من هيك.”
- **الشرح:** “الـ compiler بيترجم برنامجك كامل لكود آلة قبل التشغيل. والـ interpreter بينفّذ الكود خطوة خطوة وقت التشغيل. لغات كتيرة بتخلّط بين الاتنين: جافا بتترجم لـ bytecode، وبايثون كمان بتترجم لـ bytecode بتشغّلو آلة افتراضية. السرعة بتعتمد على التنفيذ.”
- **المثال:** C: ترجمة ثم تشغيل. Python: شغّل السكريبت مباشرة
- **الدعوة للتفاعل:** “شو كانت أول لغة تعلمتها؟ compiled ولا interpreted؟”

**149. استراتيجيات الـ Debugging** `[B]` · تحدي

- **الهوك:** “الـ bug مو وين بتفكر.”
- **الشرح:** “أول شي خلّي الـ bug يتكرر بشكل مضمون. بعدين ضيّق البحث: اقرا رسالة الخطأ، حط print أو استعمل debugger، وقسّم الكود لنصين لتلاقي وين الواقع بيختلف عن توقعك. واشرح المشكلة بصوت عالي لبطة مطاطية. غالباً بتشوفو وإنت بنص الجملة.”
- **المثال:** `print(x)` قبل وبعد السطر المشبوه
- **الدعوة للتفاعل:** “تحدّي: شو أغرب bug صلّحتو؟ أحلى حكاية بتتثبّت.”

**150. الـ Idempotency** `[M]` · سؤال

- **الهوك:** “ضغطت ‘ادفع’ مرتين وانحسب عليك مرة وحدة. كيف؟”
- **الشرح:** “العملية idempotent إذا تكرارها كتير مرات إلها نفس أثر مرة وحدة. تعيين قيمة هو idempotent. أما الزيادة فلا. الـ APIs بتستعمل idempotency keys لحتى إعادة المحاولة بعد timeout ما تعمل نسخ مكررة.”
- **المثال:** `PUT /users/7` مع `{name: 'Sara'}` آمن تكرارو. و`POST /orders` بيحتاج idempotency key
- **الدعوة للتفاعل:** “الـ DELETE هو idempotent؟ نعم ولا لا.”

## 6. Publishing Calendar

- **Two accounts:** Run the English and Arabic series as separate accounts so each audience gets the right recommendations and comment culture.
- **Cadence:** Publish one short per day per account for the first 14 days as your test window. After that, keep daily or drop to five a week. At one a day, the 150 videos last about 150 days; at five a week, about 30 weeks. Everything is pre-made, so you can publish without more production.
- **Order:** Follow the topic numbers, since later topics build on earlier ones. Within each day-block you can reshuffle freely to match the weekly rhythm below, because each block is one theme.
- **Weekly rhythm (rotate the engagement types):** Monday Quiz, Tuesday Myth, Wednesday Challenge, Thursday Debate, Friday Save, Saturday Tag, Sunday reply-video to the best comment of the week.
- **Posting times to test:** English: try a midday and an evening slot in your main audience’s time zone for two weeks. Arabic: start with evenings in Syria time (UTC+3). Both are starting hypotheses. Keep the slot your analytics favor.
- **Comment routine:** Reply within the first hour. For Quiz videos, pin the answer from the answer key 2 to 4 hours after posting, with a follow-up question. Turn the best one or two comments each week into a 20-second reply video.
- **Series labels:** Add a small on-screen label such as “Dev Basics #12” so people know there’s more and follow for the next one.

## 8. Metrics and Iteration

Review every Sunday. Don’t chase one video; look for patterns across a week.

| Metric | What it tells you | If it’s low |
| --- | --- | --- |
| 3-second hold | Is the hook working? | Rewrite the hook with a different pattern (result, mistake, myth, stakes, challenge) |
| Average percent watched | Is the pacing right? | Trim the explanation, cut filler words, add a visual change every 5 to 8 seconds |
| Comments per 1,000 views | Is the CTA easy to answer? | Switch to a one-word or one-number question |
| Saves and shares per 1,000 views | Is it useful enough to keep? | Add cheat-sheet framing and a clear “send this to…” line |
| Follows per 1,000 views | Do people want more? | Add a series label and say what’s coming next |

After two weeks, compare English and Arabic separately. Double down on the engagement types and topics that perform in each, and re-record the weakest hooks first.
